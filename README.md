# Company Scraper


A command-line tool that, given a **search query** or **seed URLs**, discovers companies and extracts
structured information (contacts, tech stack, projects, competitors, …) into JSON and CSV.

Pure Python, no API keys. Stack: `requests`, `BeautifulSoup4`/`lxml`, `pytest`.

## Features implemented

| Area | Status |
|---|---|
| **Minimal**: query or seed-URL input, URL validation, structured output, error handling | ✅ |
| **Level 1 – Basic**: name, website, emails, phones | ✅ |
| **Level 2 – Medium**: social profiles, address, tagline/description, founded year, industry, products/services | ✅ |
| **Level 3 – Advanced**: tech stack, current projects, competitors, market positioning | ✅ (heuristic) |

| CLI with options, progress output, `--level` selection | ✅ |
| Dashboard / scheduling | ❌ (use cron on the CLI) |
| Unit + integration tests, file logging | ✅ (26 tests, one command) |

## Setup

```bash
python -m venv .venv && source .venv/bin/activate     # optional
pip install -r requirements.txt
```
Python 3.9+ (developed on 3.12).

## Usage

```bash
# Search query (DuckDuckGo HTML results -> candidate company sites)
python -m scraper -q "cloud computing startups in Europe" -n 10

# Seed URLs (bare domains are fine) and/or a file with one URL per line
python -m scraper -u acme.io https://example.com
python -m scraper -f urls.txt --level 2 --format csv -o output/leads

# Offline demo against local fake sites (no internet needed) -> sample_output/
python demo.py
```

Options: `-l/--level 1|2|3`, `-n/--max-companies`, `--max-pages` (per company, default 6), `--delay` (seconds
per host, default 1), `--timeout`, `--proxy`, `--format json|csv|both`, `-o`, `--log-file`, `-v`.
Exit code is `0` if at least one company was scraped, `1` if none, `2` for bad arguments.

## Tests

```bash
python -m pytest -q
```
Tests run against a local HTTP server (`tests/fixtures.py`), so they need no network.

## Output

`output/companies.json` (`companies` + a `failures` list with the reason per failed input) and
`output/companies.csv` (lists joined with `; `). A sample generated by `python demo.py` is in
`sample_output/`. **Note:** that sample comes from local fixture sites, not live companies.

## How it works

1. **Input** – `validate.py` normalises/validates URLs (bare domains get `https://`). A query goes to
   `search.py`, which skips directories/social/media domains (LinkedIn, Crunchbase, Wikipedia, …) and
   de-duplicates by domain.
2. **Fetch** – `fetcher.py`: honours `robots.txt`, per-host delay + jitter, retries with backoff on
   network errors/429/5xx, 2 MB size cap, HTML-only.
3. **Crawl** – `crawler.py` loads the homepage, then up to `--max-pages` internal pages (contact, about,
   products, blog/news/projects, careers…) found via links and `sitemap.xml`, max 2 per page type.
4. **Extract** – `extract.py` (pure functions, easy to test) and merged per company.
5. **Output** – `output.py`; only fields up to the chosen `--level` are written.

## Design decisions & assumptions

- **No paid APIs.** Search uses DuckDuckGo's HTML endpoint; it may rate-limit or change markup. If search
  fails, the error is reported and seed URLs still work. A search engine API (SerpAPI, Brave, Bing) can be
  swapped in by replacing `search_companies` (the pipeline takes it as a parameter).
- **Search results are not always company homepages** (listicles, news). Directory domains are filtered, but
  expect some noise; seed URLs give the most reliable results.
- **Level 3 is heuristic.** Tech stack = fingerprints in HTML (scripts, asset URLs) + technology names in
  page text. Competitors = phrases like "alternative to X", "X vs Y". Projects = "currently building…"
  sentences + headings on blog/project pages. Positioning = keyword classification (leader/challenger/niche)
  with the supporting snippet. These can produce false positives; treat as leads, not facts.
- **Politeness first**: robots.txt is respected by default (`--ignore-robots` exists but is discouraged).
  Check each site's terms of service and applicable data-protection law (e.g. GDPR) before collecting
  contact data.
- One failing site never aborts a batch; failures are listed in the JSON and logged to `scraper.log`.
- Sites that render content client-side with JavaScript will yield little data (see "Not implemented").
